### RustPython no_std Issue #2362 (Extracto)

> **Can I use RustPython in Microcontrollers**
> 
> Hello all,
> I wonder if I can use RustPython in a microcontroller which uses the TockOS kernel developed in Rust. Tock currently just has example user applications in Rust, as explained here.
> I figured I might be able to use RustPython in two ways:
> 
> 1. add the RustPython dependency to my Rust applications and embed the python codes
> 2. directly load the bytecode generated by RustPython
> 
> The issue with the first option is that Tock applications are run in `#![no_std]` configurations. I could not build the RustPython dependency.

### RustPython GitHub (Extracto)

> **RustPython is in development, and while the interpreter certainly can be used in interesting use cases like running Python in WASM and embedding into a Rust project, do note that RustPython is not totally production-ready.**

> **WASM Support:**
> ```
> cargo build --target wasm32-wasip1 --no-default-features --features freeze-stdlib,stdlib --release
> ```

> **Embedding RustPython:**
> `examples/hello_embed.rs` and `examples/mini_repl.rs` may be of some assistance.

## 📊 Análise Técnica

### RustPython Dependências

| Dependência | Tipo | No_std compatível? |
|-------------|------|-------------------|
| `std` | API | ❌ Requerido |
| `alloc` | API | ✅ (com `#[global_allocator]`) |
| `libc` | FFI | ❌ Requer sistema operacional |
| `rustls`/`openssl` | TLS | ❌ Requer alloc + std |

### Exigências de RustPython

1. **Memory Allocator:** `#[global_allocator]` necessário para `Box`, `Vec`, `String`
2. **Stack Size:** ~1MB stack recomendada (não compatível com kernel stack de 8KB)
3. **File I/O:** Requer sistema de arquivos (não disponível em ring 0)
4. **Thread Local Storage:** Requer `std::thread::LocalKey`

### Conclusão da Investigação

| Aspecto | Status |
|---------|--------|
| **No_std nativo** | ❌ Não — depende de `std` |
| **Port para no_std** | ⏳ Trabalho enorme (reescrita significativa) |
| **Bridge C** | ⏳ Requer alloc manual complexo |
| **WASM** | ✅ Suportado nativamente via `cargo build --target wasm32-wasip1` |

## ✅ Decisão Arquitetural

### Rota Principal: WASM (Sprint 106-6)

**Vantagens:**
- ✅ Suportado nativamente pelo RustPython
- ✅ Sandbox isolado (não afeta kernel)
- ✅ Sem dependência a `std`
- ✅ Compilado para `.wasm` executável

**Implementação:**
1. Compilar RustPython para `.wasm` com `freeze-stdlib`
2. Executar via `wasm_rt.rs` (executor WASM existente)
3. Agentes Python como skills `.wasm` carregados da FAT32

### Rota Alternativa: RustPython Bridge C (Future)

**Vantagens:**
- ⏳ Execução nativa (sem overhead WASM)

**Desvantagens:**
- ❌ Requer portar RustPython para no_std (trabalho enorme)
- ❌ Complexidade extra de bridge C
- ❌ Risco de instabilidade

---

## 📝 Conclusão

A **Sprint 106-5** documentou que **RustPython não é no_std nativo**. A **rota principal para Python no Neural OS é WASM (Sprint 106-6)**, que já tem suporte completo no projeto via `wasm_rt.rs`.

**Próximos passos:**
- Sprint 106-6: Compilar RustPython para `.wasm` e integrar com `wasm_rt.rs`
