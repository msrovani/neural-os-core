## Achado (follow-up necessário)

O path NN está ATIVO em runtime (carga v5 ok, predição por device, cards com
src=expert_v4, gate Trinity hwexpert=LOADED). PORÉM as predições são
degeneradas: family=16 (pci_bridge) para TODOS os devices QEMU — inclusive
1234:1111 (VGA std) e 8086:100e (e1000 NIC), que deveriam ser
display/network. Hipóteses a investigar:

1. Modelo carregado @0x129400000 é o arquivo errado (auto-placement por
   tamanho desc pode ter colocado outro .bitnet nesse endereço — o parse v3
   achou magic lá também, leitura de 1024KB).
2. Modelo v4 shipped (266KB) é degenerado nos chipsets QEMU (generalização
   zero apesar do holdout ~70% — apontaria para leak de fonte no dataset).
3. Decode prediction_to_card errado para family=16 (vocab 17 famílias).

O benchmark holdout (docs/evidence/hw_expert_v4_holdout.md) mostra que o
modelo DISCRIMINA em devices nunca vistos (family 70.6% dispositivo) — então
a degeneração em runtime sugere problema de carga/arquivo (hipótese 1) mais
provável que modelo ruim. Próximo passo: sweep QEMU multi-device com o modelo
pinado em endereço dedicado + dump do token/magic do arquivo carregado.
